# 第二期培训：少花 Token，多干活

第一期帮助大家把 AI 用起来；第二期学习怎样组织任务、保留有效方法、减少返工，让同事也能接着做。适合业务、运营、研究和办公人员，不要求预先会编程。

## 课前准备

一款可以使用的 AI 工具、一个空练习文件夹、可选的 Git。课堂只使用模拟资料，不读取个人全部聊天记录，不把真实客户资料上传到外部服务。

## 课表与成果

约四小时，可拆成两个半天，课后一周完成实践。六个核心模块：省额度、存做法、Git、找工具、做好看、七天实战。附模板工具箱与来源说明。

最终产出是一份可复现的周报流程，包括模拟输入、交接笔记、skill 草稿、版本记录、前后对比和质量评分卡。原始 71 页 PDF 已保留，讲义各章节注明对应页码。

## 01 省额度

> 原始课件：第 2、4–28 页。建议用时 40 分钟：讲解 10 分钟、演示 10 分钟、练习 15 分钟、复盘 5 分钟。

### 学习目标

看懂上下文和用量，分清“处理了多少内容”“花了多少钱”“等了多久”。用同一任务做一次有质量底线的对比。

### 1. 先弄清三个词

| 词语 | 通俗解释 | 容易误解的地方 |
| --- | --- | --- |
| Token | 模型处理内容的计量单位，像计算用的小块 | 不等于汉字数，也不直接等于钱 |
| 上下文 | 本轮能参考的工作材料 | 不仅是你输入的问题，还可能有历史、文件和工具结果 |
| 缓存 | 已处理的一部分材料可能被复用 | 命中缓存仍可能计量，保存时间和折扣按产品而异 |

长会话会积累材料，也可能发生自动压缩、裁剪和缓存。“每轮重读”是便于理解的说法，不代表原文必定全部保留，更不代表所有输入都按新输入价格计费。

原 PDF 第 2、6–7 页的 97.5%、5.4 倍、83% 属于讲者个人样本。我们没有对应原始日志，不把它们写成学员的预期节省比例。订阅额度、API 账单和等待时间分开记录。

### 2. 五分钟做一次体检

1. 选一个完成过的任务，如整理周报；记录工具、版本、账号类型和日期。
2. Claude Code 用户先在命令菜单确认 /context 和 /usage；其他工具查看各自的状态或用量页面。命令不存在就记下来，不要反复试错。
3. 分别记输入、缓存、输出、额度、耗时；界面不提供的字段填“未提供”，不让模型估造。
4. 看历史是否混入无关主题、是否读入超大文件、工具结果是否反复刷屏。
5. 只选一个问题先改，再比较，不同时换模型、改提示词和装插件。

可复制给 AI：

> 先只读检查本任务的上下文和已提供用量，列出不相关历史、过长工具输出、重复规则和必需材料。没有真实数据的字段标“未提供”。给我三项建议，先不要改配置。

### 3. 继续原会话，还是另开？

| 情况 | 做法 | 先保留什么 |
| --- | --- | --- |
| 从周报换到旅行等新主题 | 新会话 | 旧任务名称和结果位置 |
| 目标没变，但历史太长 | 按工具支持压缩，或交接后新开 | 决策、文件、检查结果 |
| 连续纠正仍沿用错误假设 | 查出错点，必要时新开 | 正确口径与一条反例 |
| 准备离开一段时间 | 写交接笔记 | 当前状态和下一步 |

“三十轮换一次”是课件中的经验提示，不是强制阈值。背景仍必要时，不必为了减少轮数频繁换会话。回退聊天也不等于撤销 Git 提交、推送或外部系统写入。

交接请求：

> 请在本项目生成 HANDOFF.md，写清目标、交付物、已确定口径、修改文件、验证结果、未完成事项、风险和下一步。控制在一页，不复制整段历史；未知项写待核验。先展示内容。

示例：

~~~markdown
# 月度周报交接
- 目标：按部门整理进度，输出一页周报。
- 输入：demo-progress.csv，仅使用模拟数据。
- 口径：按 project 去重；完成率=已完成项目/全部项目。
- 决定：先列风险，不做个人排名。
- 已完成：检查重复项，P02 完全重复一行。
- 未完成：复算三部门完成率，列延期和缺日期。
- 风险：P04 无截止日期，不判断是否延期。
- 下一步：只读复算，不覆盖原表，不发消息。
~~~

### 4. 能计算的交给脚本

有 40 个表格要统计工作表行数时，让 AI 写一次脚本，后续直接运行。先约定是否含表头、空行是否计入、隐藏表怎么处理、出错是否继续。脚本输出汇总和异常，模型只读必要结果。

子代理用于可独立完成的理解和探索；它可能缩短等待，也可能增加总调用。必须把所有参与任务的总用量计入对比。选择模型时先验证质量，不能只看单价。

本课不按原 PDF 的固定价格、模型名和“预热窗口”创建自动发问任务。缓存、套餐、命令和配置均以当前官方说明及本机状态为准。

### 5. 练习与验收

用第六章模拟周报，固定输入、模型、输出要求。A 按原做法，B 只加入脚本汇总。两版都保留结果、耗时、可见用量和手工复算。

合格条件：重复项不重复算；缺失不补造；0% 不变成空值；B 的质量不低于 A。字段口径一致才能算节省率：（A−B）/A；A 为 0 或缺数据时写不适用。质量不过关就不能称为节省。

## 02 存做法

> 原始课件：第 29–37 页。建议用时 40 分钟。

### 学习目标

把高频做法从聊天里拿出来，写成同事也能执行的规则、模板和 skill。

### 1. 四类材料，各有归处

| 材料 | 放哪里 | 示例 |
| --- | --- | --- |
| 稳定、跨任务的规则 | 项目或个人规则文件 | 默认中文，只改本次范围 |
| 项目背景与状态 | README、HANDOFF | 当前输入和下一步 |
| 可重复的流程 | skill | 汇总周报并标出异常 |
| 已发生问题与改进 | FEEDBACK | 漏算一行，如何防止复发 |

规则文件保持短，细节按需读，不把全部历史资料塞进去。skill 的目录和加载选项按工具核对，不把某个 name-only 配置当作所有平台通用。

### 2. 找一个值得固化的流程

先自己列最近一周重复的请求。需要统计历史时，只使用允许的脱敏导出，脚本返回频次和匿名例句。记录任务、出现次数、耗时、常见错误、固定格式。

重复三次只是线索；优先选择频次高、输入稳定、能验收的任务。偶然问过三次的问题不一定要做技能。

### 3. 好规则回答四个问题

触发条件、具体动作、冲突处理、保留原因。例子：

“用户只要求评估时，只读检查并列建议；明确授权修改后，按本次范围实施。原因：避免讨论稿被误改。日期：2026-11-12。”

已获授权的步骤不重复确认。规则变更前看差异，变更后用正例和反例验证，不能靠越来越长的禁令代替清楚的工作约定。

### 4. 做一个最小 skill

先写草稿，先试跑，再决定安装位置。

> 请把“用部门台账生成一页周报”写成 skill 草稿。输入说明字段、单位与隐私要求；步骤包括查缺失、去重、汇总、抽查；输出风险、进展、待确认。缺输入先报告，禁止虚构。先用模拟台账验证，不直接安装到全局。

目录示例：

~~~text
weekly-report/
  SKILL.md
  templates/report.md
  scripts/summarize.py
  references/checklist.md
~~~

说明草稿：

~~~markdown
---
name: weekly-report
description: 根据部门进度台账整理周报，汇总完成情况并标注延期和缺失项。
---
输入：project、department、status、deadline、note。
步骤：查字段；按主键去重；列冲突；按部门汇总；抽查三行。
输出：风险、部门完成率、已完成事项、下周安排、待确认。
失败处理：缺少主键时不去重；不擅自覆盖原表。
验收：数量可复算；未知有标记；不凭空增加项目。
~~~

换一份文件就失效，通常是输入约定没写清；照截图点按钮容易失效，是把界面细节当成了业务规则。先讲目标和验收，再写平台操作。

### 5. 问题账本不是“已修复”清单

| 问题 | 根因 | 改法 | 复测 |
| --- | --- | --- | --- |
| 部门丢了 | 分组时过滤空值 | 空值列为待归属 | 加一行空部门 |
| 0% 变空白 | 把 0 当成无值 | 区分 0 和缺失 | 各造一行对照 |

还要记日期、用户原话、复发次数和负责人。声称修好时附复测输出或截图；再次发生就重查根因，不只是把状态再改一次。

### 6. Hook、定时与共享

Hook 是在特定时刻运行的一小段动作。写日志、查文件等确定性工作用脚本；理解内容和生成结果才考虑模型。定时同步不必每轮执行，先测耗时和失败影响。

多工具共享按“共同规则+工具差异”分层，先单向同步。两边同时修改时先对比，不直接相互覆盖。

练习提交：skill 草稿、模板、正例、异常例和反馈表。验收：同事不用看原聊天也能执行；缺字段会报告；原始输入不被覆盖；三条验收均有证据。

## 03 Git

> 原始课件：第 38–48 页。建议用时 40 分钟。

### 学习目标

先用不含秘密的空目录练“保存与找回”，再考虑远端协作。Git 是本地版本工具，GitHub 是托管平台，二者不是一件事。

### 1. 六个词串成一条路线

| 词语 | 类比 | 实际作用 |
| --- | --- | --- |
| Repository 仓库 | 有历史的文件夹 | 保存文件和变更 |
| Commit 提交 | 带说明的快照 | 在本地记录一组修改 |
| Branch 分支 | 试验轨道 | 隔离新做法 |
| Push 推送 | 把快照送走 | 分享已有提交 |
| Pull 拉取 | 接收并整合 | 可能发生冲突，不只是复制 |
| PR 合并请求 | 请人检查 | 讨论、验证、合并 |

提交不等于上传。未提交文件也不自动进入普通提交历史，不能指望 Git 找回一切。

### 2. 本地练习，不连远端

在新建的 ai-config-practice 空目录操作，不在业务仓库里练习：

~~~powershell
git --version
git init
git status
~~~

没有 Git 先安装；已在别人的仓库中就停止，换目录。生成演示 README.md 和忽略规则：

~~~gitignore
.env
.env.*
!.env.example
*.pem
*.key
tmp/
node_modules/
~~~

.gitignore 不会从历史移除已提交的秘密。私有仓库也不能放密码；误提交凭据时要撤销或轮换，不能只删除最新文件。

### 3. 两次提交，说明改了什么

先检查，再逐个加入：

~~~powershell
git status --short
git add README.md .gitignore
git diff --cached --stat
git diff --cached
git commit -m "Add practice workflow and ignore rules"
git log --oneline -3
~~~

需要身份配置时，只配置本人认可的姓名邮箱和这个练习仓库，不随意改全局。随后修改一句话再做第二次提交，每次只加入获准的文件。

### 4. 找回旧版，先看再恢复

用日志找到第一次提交 ID：

~~~powershell
git log --oneline -5
git show FIRST_COMMIT:README.md
~~~

FIRST_COMMIT 要替换为真实 ID，不能原样运行。确认旧内容正确、当前工作已保存后，让 AI 只恢复这个演示文件、展示差异，再做一个写明原因的新提交。本课不使用 reset --hard 或强推作为恢复方法。

### 5. 共享时再加 GitHub

先确认个人/组织、公开/私有、读写人员，启用可恢复的双重验证。创建远端、推送等动作需要明确授权；之前只准备清单和差异。重要变更通过 PR，不直接覆盖他人工作。

配置库只放规则、模板、脚本和不含秘密的示例。大媒体单独存放，具体限制查当前 GitHub 文档，不把原课件的固定大小写成永久规则。

可复制请求：

> 检查练习目录，列出已跟踪、未跟踪和忽略文件。检查秘密、个人信息和大文件。先给拟提交清单与说明，不创建远端、不提交、不推送、不覆盖现有改动。

练习提交：两次提交、一次旧版查看、一次带原因的恢复记录。验收：分清已保存、已提交、已推送，能用提交 ID 找到版本，没有上传秘密。

## 04 找工具

> 原始课件：第 49–58 页。建议用时 35 分钟。

### 学习目标

根据任务选方法，完成一页工具评估。不要为了安装工具而制造需求。

### 1. 分支判断，不必逐个安装

| 任务特征 | 优先选项 | 例子 |
| --- | --- | --- |
| 一次性、材料少 | 直接对话 | 改写一封草稿 |
| 高频、格式固定 | 模板/skill | 周风险报告 |
| 数据在外部系统 | 有限权限连接器 | 读取指定资料目录 |
| 大量、规则可计算 | 脚本 | 汇总四十张表 |
| 过程长且可独立 | 子任务/子代理 | 查一组资料后回摘要 |
| 错误代价高 | 原始来源+独立复核 | 对外报告、关键计算 |

可以组合，但每加一件工具都说清已有方案为何不够；有稳定可用的简单方法就先用它。

### 2. 安装前检查三件事

| 方面 | 问题 | 证据 |
| --- | --- | --- |
| 冲突 | 改哪些文件、权限、规则 | 差异清单与备份 |
| 成本 | 安装维护、上下文、调用和等待 | 真实测量，无数据就标未知 |
| 效果 | 同一任务是否更好 | 相同输入和验收的两份结果 |

再记录官方来源、维护日期、许可证和退出方案。字符数只能作为材料大小线索，不能当准确 Token 或账单。测试放到独立目录，不直接改正式环境。

> 先不要安装。依据官方说明与我提供的配置，列出用途、依赖、权限、冲突、维护和回滚。读不到的文件写未读取。设计同一任务的质量、时间、总用量对比，不用下载量代替适用性。

### 3. 标准答案回到原始来源

API 参数看对应版本文档，词表看发布机构和版次。每条重要事实记录结论、原始来源、日期/版本、适用条件、核验状态。链接打不开就写待核验，不把搜索摘要自动升级成事实。

### 4. 复核不是“夸一下”

把成品、原始输入和验收标准交给没有参与制作的审阅者：找编造数字、漏项、错误计算、不适用命令和缺失边界。回到证据决定采纳；两个模型一致也不证明事实正确。敏感材料先脱敏，并确认服务可用范围。

### 5. 听写术语表

维护 20–100 条常用词，列标准名称、缩写和易错听写。普通文字可以按读音和上下文纠正；收件人、金额、基因名、药名、路径等关键值必须确认后执行，不能靠谐音猜测。

练习：对周报任务比较直接问、模板和脚本，至少记录一个失败样例。验收：选择与需求匹配；有来源、成本口径和退出方案；未把缺失写为零；没有扩大权限来强行跑通。

## 05 做好看

> 原始课件：第 59–68 页。建议用时 35 分钟。

### 学习目标

把“再好看一点”变成一张风格表、两种尺寸的检查和一次朗读改稿。

### 1. 先问谁看、看完做什么

周报要迅速找到风险，讲义要讲清步骤，课件每页只解决一个问题。不能把长文章切成一堆卡片就叫演示稿。

| 项目 | 本次练习决定 | 检查方法 |
| --- | --- | --- |
| 字体 | 系统中文字体、正文清晰 | 无缺字、正常缩放可读 |
| 颜色 | 深绿标题、蓝色链接 | 不只靠颜色表达状态 |
| 标题 | 写具体动作或结论 | 单读标题就知重点 |
| 图表 | 单位、时间、来源齐全 | 不看讲稿也能懂 |
| 手机 | 主要内容单列，表格局部滚动 | 页面整体不横向溢出 |
| 控件 | 操作易点，标签不挡正文 | 手机上逐个点击 |

另列“我总在删”：无来源统计、口号、重复标题、无意义标签、与任务无关装饰。但来源日期、适用版本和风险说明不能为了简洁删掉。

### 2. 正面说要求

差请求：“做得高级一点，别千篇一律。”

好请求：

> 给业务同事做培训，每页一个问题，标题写动作或结论，正文给例子、步骤和验收。中文字体清晰，手机单列，图表有单位和来源。先出一页样稿，检查后再扩展。

### 3. 两种尺寸检查

练习尺寸为 1440×900 和 390×844。查截断、重叠、整体横向滚动、表格局部滚动、对比度、中文缺字、图片清晰度和可点击性。截图是证据，不能代替交互和数字复算。

### 4. 十二项评分卡

0 分=影响理解或不能用，1 分=可用但需改，2 分=清楚可用。

| 项目 | 得 2 分的证据 |
| --- | --- |
| 结论 | 标题说清主张，不用口号 |
| 层次 | 标题、正文、注释易区分 |
| 字体 | 中文清晰，无缺字 |
| 颜色 | 有主次且不单靠颜色 |
| 图表 | 单位、范围、来源完整 |
| 间距 | 对齐一致，不挤不散 |
| 桌面 | 不过宽，无重叠 |
| 手机 | 页面无横向溢出，操作可点 |
| 留白 | 重点突出，不用装饰填满 |
| 语言 | 当面对同事说也自然 |
| 事实边界 | 模拟、推断、经验标清 |
| 可操作性 | 有输入、步骤、验收 |

满分 24 分，80% 至少是 **20 分**，并且不能有 0 分。门槛是本课程练习标准，不是行业认证，不证明所有事实已正确。

### 5. 说人话不等于编数字

“赋能业务闭环、显著提升效率”如果没有证据，就改为：“先把收台账、查缺项、汇总进度分三步，周五试一次，记录耗时和返工。”

有真实测量后再写变化幅度和适用条件，不能为了具体而编造“省了二十个工时”。

> 把文字改成对同事当面说的话，保留事实、数字、条件、来源和不确定性。删空话，不新增业绩。给改前/改后与理由，再读成一分钟口播。

提交：一页样稿、双端截图、评分卡、口播稿。验收：至少 20/24 且无零分，关键按钮实测，同事能复述下一步做什么。

## 06 七天实战

> 原始课件：第 69–70 页；本章模拟数据、答案和七天安排为新增教学内容。

### 1. 用同一份输入串起全课

以下都是模拟项目，保存为 demo-progress.csv：

~~~csv
project,department,status,deadline,note
P01,销售,已完成,2026-11-13,说明已审核
P02,销售,进行中,2026-11-09,等待资料
P03,研发,已完成,2026-11-14,测试通过
P04,研发,未开始,,负责人待确认
P05,运营,进行中,2026-11-15,渠道确认中
P02,销售,进行中,2026-11-09,等待资料
~~~

约定练习日期是 **2026-11-12**，不是让程序永远使用这个日期。按 project 去重；完全重复保留一行，同主键不同内容列冲突，不能随意删。完成率=已完成去重项目/全部去重项目；截止日期早于练习日期且未完成才延期，缺日期列待确认。

手工答案：有效项目 **5**；销售 **1/2=50%**，研发 **1/2=50%**，运营 **0/1=0%**；延期 **P02**；缺日期 **P04**。任何工具都和这个基准对照。

### 2. 一张完整任务卡

> 输入为上面 CSV，日期和字段口径按约定。生成一页周报：先查重/缺失，再按部门统计，最后列延期和待确认。不得虚构负责人、日期或完成事项，不做个人排名，原文件只读。给出各项数量的计算过程。

### 3. 七天只抓一个流程

| 天数 | 动作 | 时间参考 | 留下什么 |
| --- | --- | --- | --- |
| 第 1 天 | 原做法跑一次，查看用量 | 15 分钟 | 输出、耗时、可见用量 |
| 第 2 天 | 写交接，新会话接班 | 15 分钟 | HANDOFF 与接班结果 |
| 第 3 天 | 提炼 skill 草稿 | 30 分钟 | 说明、模板、异常测试 |
| 第 4 天 | 本地仓库，两次提交 | 30 分钟 | 提交 ID 与清单 |
| 第 5 天 | 脚本法跑同一周报 | 30 分钟 | 输出、手算对照、记录 |
| 第 6 天 | 一页展示与双端评审 | 30 分钟 | 截图、评分、改三处 |
| 第 7 天 | 同事复现并复盘 | 20 分钟 | 使用说明与一页小结 |

五分钟先查用量或写交接；半小时先试一个 skill；一小时先完成本地版本记录、样例和复现。时间仅为计划参考，不安排自动发问或唤醒电脑。

### 4. 对比表

| 指标 | A 原做法 | B 新做法 | 判定 |
| --- | --- | --- | --- |
| 数量与字段 | 记录错误 | 记录错误 | B 不能退步 |
| 有效项目 | 应为 5 | 应为 5 | 与手算一致 |
| 等待/人工耗时 | 分开测 | 分开测 | 不混合口径 |
| 返工次数 | 写明定义 | 同一定义 | 不只看字数 |
| Token/额度 | 无则未提供 | 相同口径 | 不混 API 与订阅 |
| 同事复现 | 能/不能及原因 | 能/不能及原因 | 留操作证据 |

### 5. 结业检查

提交任务卡、模拟输入、最终周报、交接、skill 草稿、Git 记录、对比表、评分卡和待改事项。没有证据就标未完成。

老师问四个问题：为什么选这个方法？哪条数据证明有效？哪里还需人工判断？改坏怎样恢复？能回答并复现，才算把技巧变成了能力。
