## 2. 文档结构基线

1. 总体概览
   - 愿景：以积木和编程为载体，保护好奇心、想象力和问题意识。
   - 主张：通过真实问题培养科学思维、工程实践和技术向善。
   - 双螺旋：科学思维层（观察—假设—实验—迁移）与工程实践层（需求—设计—实施检验—迭代发布）。
2. 成长阶段
   - 科技启蒙与兴趣萌发
   - 进阶深化：系统思维、传感器、条件与循环
   - 青少年贯通：Python/C++、算法和系统方案
   - 高等教育：跨学科研发
   - 职业期：国防科技/民用技术转化与伦理
3. 阶段实操
   - 软件 + 硬件 + 应用
   - 低龄阶段以积木、Scratch、WeDo 等降低抽象门槛
   - Code 1/2/3 逐级增加条件、循环、变量、传感器、函数和 Python 衔接
4. 执行节奏与成长画像
   - 每周 1-2 次课，每次围绕一个主题做项目
   - 家庭以复述“做了什么、怎么做的”帮助巩固逻辑
   - 以作品和过程证据为主，考试/赛事只作为阶段性检验

## 4. 本次交付内容标准

### 专业成长与实践记录

用于记录一次完整的“目标—实践—证据—复盘”闭环。必须能填写专业方向、问题、资料、实践过程、成果链接和下一步。

### 成长计划

用于把方向拆成可执行的近期行动。必须包含成长方向、当前水平、目标水平、截止日期、本周行动、预计用时、完成情况和需要支持。

### 阶段方案

用于把长期成长拆为阶段和里程碑。必须包含阶段时间范围、核心问题、课程/工具、阶段产出、完成标准、复盘和调整。

### 成果展示

用于面向家人、老师或同伴讲清楚作品价值。必须包含成果名称、问题背景、过程证据、技术要点、结果、链接/文件、展示对象和下一次迭代。

## 5. 设计与内容决策

- 首屏先回答“我现在在哪、下一步做什么”：项目标题、三栏 Tab、阶段路径和任务进度同时可见。
- 目录和文档分开计数；子栏目是 folder，模板是 text。
- 任务勾选只保存本地 UI 状态，不写入数据库，避免为轻量交互改 schema。
- 所有模板保持空白可编辑；可以写填写提示和验收标准，不填入个人姓名、年龄、成绩、健康或行程。
- “军事”示例统一转为民用/安全技术主题：灾害响应、环境监测、无障碍、节能、校园安全。不得提供武器制作、伤害或规避监管的可操作步骤。
- 外部链接只作为用户补充资料的入口，正文不依赖外部 CDN 或登录态。

## 6. 质量基线

- 内容覆盖：四类文档每类都有目标、行动或阶段、证据、复盘或下一步。
- 导航：项目首页 -> 三个子栏目 -> 文档详情 -> 返回项目/场景；folder 参数越界时回到项目首页。
- 交互：Tab、任务复选、进度数字、刷新恢复、折叠目录、键盘焦点均可用。
- 响应式：390px 和桌面宽度无横向滚动；表格和长标题换行，不遮挡按钮。
- 权限：未登录 401；访客只读；管理员可新增、编辑、删除和调整排序。
- 工程：npm test、npm run typecheck、npm run lint、npm run build 全部通过。
