# “解构世界”-科技特长（专业）交付标准与执行提示词

版本：2026-11-10 · 适用项目：VaultView / 爱的城堡 / 解构世界

## 1. 交付标准

### 内容标准

- 项目首页必须说明：项目目标、五阶段路径、四类资料入口、下一步动作。
- 四类资料固定为：专业成长与实践记录、成长计划、阶段方案、成果展示。
- 每类资料都必须有“目标—行动/阶段—证据—复盘—下一步”字段；空白模板可直接填写。
- 内容只提供通用方法、字段说明、验收标准和安全边界，不虚构个人信息、成绩、健康或外部事实。
- Topics 采用 1 个周期标签 + 1–2 个主题标签，首页和详情一致显示。

### 交互标准

- 项目首页、四类资料、文档详情、返回项目、刷新恢复均可用。
- 工作台四个 Tab 与四类文档一一对应；点击 Tab 能定位对应文档入口。
- 内容目录可折叠；键盘可以聚焦、切换和提交；访客只读，管理员可编辑。
- `project` 或 `folder` 参数无效时回到合法项目首页，不显示空白或越权内容。

### 视觉与响应式标准

- 390px 手机宽度和桌面宽度均无横向溢出；标题、标签、表格不重叠。
- 首屏同时呈现项目名、当前阶段、资料数量和下一步按钮；卡片不嵌套卡片。
- 类型图标、主题标签和状态色有稳定含义；颜色不依赖单一色相。

### 证据与工程标准

- 运行 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build` 全部通过。
- 至少覆盖：四类资料存在且字段完整、Tab/深链导航、刷新恢复、访客权限、管理员 CRUD、390px 溢出检查。
- 审核记录必须区分事实、推断、未验证项和剩余风险；不得把模板示例写成个人事实。

## 2. 执行提示词

### 内容策展提示词

你是 VaultView 的专业成长内容策展人。请以“解构世界”-科技特长（专业）为主题，检查项目首页和四类模板是否形成“目标—行动/阶段—证据—复盘—下一步”闭环。补足字段说明、填写提示、验收标准和技术向善边界；只写通用方法和空白模板，不虚构个人事实。每份文档只解决一个场景，Topics 使用“周期 + 1–2 个主题”。

### 交互实现提示词

你是资深 React/TypeScript 工程师。沿用现有 Content 树、路由参数、Markdown、管理员 CRUD 和中文视觉系统，不新增数据库 schema。把专业成长工作台做成四个可切换 Tab：专业成长记录、成长计划、阶段方案、成果展示；Tab 与文档入口可互相定位，刷新后保留项目/目录位置。保证键盘可达、访客只读、管理员可编辑、无效参数回退和 390px 无溢出。

### 审核提示词

你是独立交付审核员。只依据 CHARTER.md、本标准、research/BRIEF.md、当前代码和测试证据审核。逐条检查内容闭环、四类资料一一对应、导航和返回、刷新恢复、权限、标签口径、响应式和工程命令。发现 Critical/Major 必须先修复；Minor 要写明影响、证据和后续建议。最终只有在没有 Critical/Major 且所有硬检查通过时才给出 `USE: yes`。
