# AI辅助生成的精准医疗行业简报

## 角色

- 主编：只汇总已返回的调研结果，去重、核对时间窗口、分组并写出业务点评。
- 子代理：各自只负责一个栏目，不替其他代理补写，不把搜索摘要当作事实。
- 质检员：在发布前检查栏目、字数、来源、日期、占位文本和重复新闻。

## 范围

聚焦世和基因相关的精准医疗：肿瘤 NGS、MRD、IVD、早筛、液体活检、多组学、医疗 AI、肿瘤诊疗与支付。不得把未经来源确认的合作关系写成事实。

## 来源等级

监管审批、支付、临床试验和财务事实优先使用官方原文、注册数据库、论文原文、公司公告和财报。主流媒体可补充背景，但必须标注媒体来源；转载不算多个独立来源。

## 输出规则

- 固定五栏：世和动态、同行与竞对、监管与支付、科学与突破、上下游伙伴。
- 每条消息最多 300 个中文字符（来源元信息不计入），每栏最多 3 条。
- 每个有可靠新增的栏目以 2 条为目标、最多 3 条；主编应优先补足第二条不同事件。只有完成覆盖检索仍不足时才少于 2 条，并在 `coverage` 写出缺口原因。数量不能通过重复事件、旧闻、搜索摘要或无原文线索补齐。
- 每条都要有标题、事实、关注点、对精准检测/世和业务的点评和至少一个来源 URL。
- `attention` 必须写实质关注点；重大或超预期信息设置 `severity: "important"`，由页面展示 `⚠`。
- 事实、关注点和点评分开写；点评是业务分析，不是诊疗、投资或法律建议。
- 使用北京时间；日报窗口默认为前 24 小时。首期回看可使用 7 天，但必须写明窗口。
- 没有可靠新增时保留栏目，并写“本时窗未发现经核实新增”。
- 禁止 `example.com`、占位标题、未来发布日期、无来源消息和无法解释的推测。
- 来源使用可直接定位事件的原文永久链接；新闻目录、搜索结果和首页不能替代独立公告。
- 研究首发日期与公司传播日期分别核对。窗口内公司新公告引用旧论文时，归入企业动态并明确两个日期，不称为本周新论文。
- 审批报道必须保留人群、适应证和关键限制；队列采集数量与排除后的分析数量不得混写。
- 本期要点优先给出有证据支持的业务关注顺序及理由；不使用“本版扩充了”等制作过程介绍。

## 发布模板

```markdown
# PM·每日行业简报｜YYYY-MM-DD

> 数据窗口：...；生成时间：...；状态：已发布

## 本期要点
...

## 01 世和动态
## 02 同行与竞对
## 03 监管与支付
## 04 科学与突破
## 05 上下游伙伴

## 来源与方法
...
```

发布前在仓库根目录运行：`npm run precision:validate -- <brief.json>`，再运行 `npm run precision:publish -- <brief.json> [项目ID]`。发布共用后端校验与事务，失败不覆盖上一版。

已发布运行不可原地修改。内容修订必须使用新的`runKey`，同日新版本替换当前展示并保留历史；相同`runKey`仅接受内容完全相同的幂等重试。
