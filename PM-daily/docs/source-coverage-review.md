# 世和市长质量奖公示漏检复盘

核验日期：2026-11-12（北京时间）。

## 找到的消息

南京市市场监督管理局11月11日的[拟授奖公示](https://amr.nanjing.gov.cn/gkml/202611/t20261111_6037261.html)在正文内嵌名单的“市长质量奖（组织）提名奖”类别下，列有南京世和医疗器械有限公司。公示期为11月11日至17日。

[世和基因公司简介](https://zh.geneseeq.com/qiyejianjie.html)明确这家公司是旗下子公司。准确表述为“世和基因旗下南京世和医疗器械有限公司列入2026年度南京市市长质量奖组织提名奖拟授奖名单”，不能写成“世和基因已获市长质量奖主奖”。这与8月进入评审名单、11月6日邵阳省青年科技奖报道是不同事件。

## 漏检原因

原运行的公司栏目仅记录世和官网新闻、会议活动、IPO及财经媒体，没有检查地方政府公示，也没有以子公司法定名检索。原sources.json没有南京市场监管局/政府/江北新区入口，队列代码也不读取这份来源配置，代理收到的采集任务缺少可逐项执行的覆盖清单。schema只能检查coverage是否非空、长度合格，不能证明这些网页已查。

本次关键词搜索多次返回8月旧公示，直接打开[市场监管局首页](https://amr.nanjing.gov.cn/)的最新通知公告后才发现11月原文。详情直开一度失败，循首页真实链接点击后可读。公示附件直接嵌入HTML；文件下载栏为空不能视为没有名单。

此前“世和无新增”的判断过早：至少应保留此候选及时间待核原因。

## 修复内容与使用

来源配置增加三个有官网证据的品牌/法定名称、公司动态及简介、南京市场监管局/市政府/江北新区入口，并覆盖公示、拟授奖、提名奖、质量、专利、注册和IPO。

`precision:queue`的有任务查询、建立、领取现在返回`researchPlan`；空队列及失败登记保持原语义。计划生成使用来源配置，所有检查初始都是`not_started`，不进行联网采集。来源配置错误在建立/领取前检查，避免因配置错误留下半领取状态。

对于既有运行，可执行：

```powershell
npm run precision:plan -- PM-daily/runtime/brief.json
```

命令读取原运行身份和窗口，返回带五任务计划的JSON，不建立新运行，也不更新当前日报。计划单独用于分派；日报JSON仍严格遵守现有schema，不加入researchPlan字段。

代理须同时检查官方最新列表和独立搜索，使用所有有证据的主体名，打开正文表格、内嵌及独立附件。在rawReport中逐项留存checkId、实际URL、访问时间、检索方式、候选和排除理由。仅母公司检索、只打开首页或仅复制计划都不构成已完成覆盖。必查入口/关键原文失败或有未决相关候选时不能写no_news；失败不覆盖旧版。

## 日期与边界

公示仅给生成日期和落款11月11日，没有时分。原窗口为11月11日09:00至12日09:00，现有证据不能证明它在起点之后发布。现有schema采用日期整日区间与窗口重叠的规则，同稿Guardant也只有日期；所有机构必须一致标注日期精度，不能因未知而只对这条公告特殊排除，也不能编造精确时间。新规则要求保留候选和边界未决原因，不将公示期当作发布时间。

## 验证范围

回归针对已证实子公司、地方政府入口、计划不冒充采集、原身份/窗口保持、空任务、配置及CLI错误、历史发布兼容等行为；隔离数据库测试不操作真实日报。具体执行结果见本次marathon审计记录。

本次修复不改历史日报、当前已发布版、brief schema或后端API。该工具生成检索计划，实际覆盖和事实核验仍须代理执行、主编审核；不能宣称全网召回率或未执行的采集已验证。既有失败运行也不会因补一条企业消息而自动发布。
