# 基础生活 健 健康管理

本项目位于生活场景，服务个人和经同意管理的家人。目标是用尽可能少的记录支持每日行动、持续观察和就医沟通，不把家庭管理工具包装成在线医疗服务。

## 内容与工作方式

项目内提供九份可读、可通过原资料管理编辑的指南：30天启用、健康档案、生活方式、测量与趋势、症状安全、药单与慢病、预防与家庭医生、行动复盘、使用与隐私。指南包含分工表、空白模板和直接来源链接，没有预填家庭成员、疾病或处方。

操作以本人的真实需要为起点：建最小档案 → 每人最多三个未完成阶段重点 → 记录有指征的指标 → 跟进预约和结果 → 每周减少无用记录。行动应有责任人、期限和完成依据。PDCA用于安排复盘，COM-B用于理解执行困难；二者不是临床风险评分。

## 数据与服务边界

每个登录账号在每个健康项目拥有独立家庭工作区；取得项目访问权不意味着可以查看他人的健康数据。成年人先同意记录，儿童由监护人管理。公共指南中不要写个人病史、药单或检验数据。共用同一账号会共享该账号的所有家庭数据，首版不提供跨账号细粒度家庭授权。

首版不提供在线医生、诊断、处方、自动药物相互作用审查、自动异常监护、后台推送、报告OCR、设备同步和文件上传。填写家庭医生联系方式不表示该医生已接入服务。报告内容先以文字摘要整理，纸质或电子原件保留在用户既有安全位置。

打印与JSON等导出会生成敏感副本，应保存在可信设备与私有目录；删除工作区不会撤回副本。按账号权限隔离不等于数据库静态加密，运行主机、备份与导出文件需另行保护。局域网HTTP只用于可信网络，外网使用需要HTTPS与受控访问。

## 数据初始化

`backend/prisma/health.ts` 中 `seedHealth` 只补建缺失节点：正式项目标记唯一；项目必须在生活场景根目录下；指南按稳定标记识别，同时保留按标题匹配的已有编辑；冲突类型和重复标记会中止事务，不自动合并或覆盖。seed不会自动给任何用户增加项目授权。

独立初始化入口为 `backend/prisma/init-health.ts`，由根项目脚本集成后运行。不要为了增加本项目执行会覆盖其他项目的全库重置。后续新增内容仍使用现有资料管理方式。

## 日常使用

1. 首次打开点“建立第一份档案”，先填写过敏、药物和紧急联系，其他信息以后补齐；每份档案确认本人同意或监护人权限。
2. “今日”合并到期行动、就医预约、待结果、复诊和药单核对。点击事项更新原记录；处理完后更新后续日期，避免重复登记同一提醒。
3. 在“日常记录”选择一位成员，再按需要记录指标。图表仅连接该成员同一项目最近20条观察值，不显示自动医学正常区间；表格保留原始时间、单位与条件。
4. “行动计划”最多保留每人三个未完成阶段重点。每日/每周行动填写完成依据后生成下一期，逾期不补造历史。页面清单不等于手机推送通知。
5. 就诊前到“就医协作”核对完整药单，打开该成员摘要，打印或下载文本。就诊后填写医生结论、结果与下一次安排。
6. JSON导出是资料副本，当前不提供自动恢复导入；达到记录数或100KB工作区限额时，先导出归档并有选择地删除已不需要的旧记录。单项上限：12位成员、600条测量、150条行动、药单/就医/回顾各100条，以先到的限制为准。

保存遇到其他页面已更新时，系统保留已尝试提交的草稿并提示重新加载；不会静默覆盖。清除本账号资料后，数据库中的健康正文置空，版本保留以防旧页面重新恢复被清除内容。
