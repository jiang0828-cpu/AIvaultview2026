# 消费支出｜跨平台比价

## 用户目标

用户要求：在生活场景新增“消费支出｜跨平台比价”，保留 React、Express 和现有权限，使用本机 Python 服务完成参数标准化、严格匹配、到手价、前三推荐、报价导入、历史和收藏。

用户将输入商品需求，确认条件后搜索，区分演示与实际报价，复核推荐、导入报价并收藏结果。

错误交付包括：配置不符商品进入前三、未知运费被算成免费、不同币种混排、演示报价冒充实时价格、未授权用户读取他人记录。

## 交付标准

| ID | 标准 | 验证 |
| --- | --- | --- |
| G1 | 标记项目、七份文档幂等写入，不覆盖编辑 | seed 测试与当前数据库验证 |
| G2 | Python SQLite 独立持久化，内部令牌，用户及项目隔离 | Python API 测试 |
| G3 | 严格型号/参数/成色匹配，未知费用和货币安全，前三可解释 | Python 单元测试及三个 fixtures |
| G4 | Node 登录、授权、可信身份转发、服务异常统一处理 | Node 接口测试 |
| G5 | 表单、条件确认、结果筛选、导入修改、历史、收藏可操作 | 前端逻辑测试与浏览器流程 |
| G6 | eBay 官方适配器，无授权平台如实降级 | mock HTTP 测试、平台状态 |
| G7 | 桌面/移动端无页面横向溢出，比较表单独滚动 | 浏览器尺寸与截图 |
| G8 | 测试、类型、lint、build 通过并提供局域网入口 | 验收报告 |

## 边界

不抓取需登录个人页、不绕过验证码、不自动下单、不存支付信息、不引入 Redis/Docker。不修改既有 Prisma schema，不改动其他项目数据。真实平台授权由环境变量提供；没有凭据时不宣称实时跨平台搜索已经开通。

## 运行方式

balanced；3 个构建 worker（Python、Node/seed、前端），主线程负责集成、启动、验证。只使用现有工具和免费路径。保留当前脏工作区，不为严格 gate 擅自提交他人改动；最终对交付文件及测试证据独立复核并如实披露检查边界。
